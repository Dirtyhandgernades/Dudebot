## P0-1: fail-closed bounded vendor request budget on ambiguous responses

Before this change, a provider's HTTP 200 response with malformed/unknown status or an ambiguous provider error could be censored for the current row yet allow the same provider's remaining paid requests to proceed. A successful HTTP 200 response with a zero-padded numeric `x-ratelimit-remaining: 00` also failed to stop the budget because only literal `"0"` was recognized. These are **offline-diagnosed quota/entitlement safety gaps**, not evidence of a live vendor incident.

Implemented [research-only commit 2762b3784869f1a39e586e08c1c1f1af793ef05c](https://github.com/Dirtyhandgernades/Dudebot/commit/2762b3784869f1a39e586e08c1c1f1af793ef05c) in `backtest/obsidian_two_provider_close_reconciliation.py`. Provider-neutral intake now classifies absent/unexpected vendor status explicitly; malformed response, ambiguous provider error, oversized body, or malformed transport status stops that provider's remaining requests with `UNVERIFIABLE_PROVIDER_RESPONSE`. A numeric zero-padded remaining-quota header stops requests with `RATE_LIMIT`. The first original receipt/error is retained; all skipped ticker/date rows remain present and censored. Existing explicit HTTP 401/403/429 classifications take precedence. No automatic retry, altered request maximum, or live fetch.
