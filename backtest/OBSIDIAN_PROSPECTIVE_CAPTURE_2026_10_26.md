# OBSIDIAN independent prospective capture — research only, 2026-10-26

This is an **as-of read-only provider-universe collection mechanism**, not a live trade signal, verified complete SMG market, historical gap repair, broker locate, or profitable strategy. It uses GET only on Alpaca's assets and SIP stock snapshots endpoints, never order endpoints. No live alerts, production workflow, or main branch is changed. Credentials are read from pre-existing GitHub Actions secrets at runtime; the code neither creates nor modifies them and never stores credentials in artifacts.

## What it captures

At an allowed **2:45:00–2:58:00 PM America/Chicago** weekday time, the isolated research workflow can capture all active NYSE/Nasdaq US-equity symbols **returned by Alpaca's asset API**, in deterministic sorted batches of up to 100. A provider error, unrequested snapshot symbol, empty universe, duplicate ticker, or exhausted request budget fails closed. The collector also rechecks the Central closing-window gate after the asset response, immediately before each SIP snapshot request, after each response, and at completion; crossing 2:58 PM Central aborts the capture rather than silently including out-of-window evidence. Four synthetic cutoff-boundary tests cover these failure points. This is intentionally conservative: a slow provider or GitHub runner can result in no artifact rather than an invalid prospective sample. The asset API scope **is not evidence of full-market recall or the SMG-eligible universe**. The collector also rejects **non-monotonic or naive capture clocks**: asset receipt, each batch request/response, and final completion must be ordered consistently. A backwards clock jump aborts the entire run rather than mislabeling future provider observations as earlier as-of evidence. This is tested with synthetic clock regressions; it does not establish external clock synchronization or provider latency. The `universe.jsonl` ledger preserves every returned NYSE/Nasdaq symbol, including missing SIP snapshots, stale/future last trades, unsupported ticker formats, and no-setup cases. The `manifest.json` records capture times, source endpoints, coverage counts, raw universe and candidate SHA-256 digests, and unverified requirements.

`candidates.jsonl` contains **price-only** A watch rows for as-of changes from previous daily close between -2% and -15%, and B exhausted-drop rows for changes <= -25%, based on a last trade no more than five minutes old. This is **not** an independent technical confirmation, a verified short, or a Category C reversal detector. Unclassified symbols remain in the universe ledger and denominator. There is no outcome or hindsight field in the capture. A prior daily bar's `t` denotes the bar start, **not** the moment the provider returned it; its retrieval is evidenced by the raw snapshot and `received_at`. To avoid treating multi-session-old last daily bars as a fresh previous close, the research capture censors a previous-bar timestamp more than four Eastern calendar days before the decision (`STALE_PREVIOUS_CLOSE_BAR`), allowing ordinary weekends and one-day market holidays while conservatively excluding exceptional longer closures. Capture-window checks reject naive timestamps rather than interpreting the runner's timezone. These fail-closed guards were validated with 27 hosted offline tests in Actions run `40281976395` on 2026-10-26; this does not validate provider access or real market coverage.

Every candidate has **unknown common-stock type, shares/market cap, halt/corporate actions, SMG short acceptance and borrow**, so the existing frozen `obsidian_prospective_journal.py` must mark it `BLOCKED`, not actionable. Missing or incomplete minute bars remain blocked. If there are no candidate rows, the manifest explicitly reports `NO_CANDIDATES` rather than fabricating a trade. The write-once directory prevents silently overwriting a prior capture.

## Triggering and validation

`.github/workflows/obsidian-prospective-capture.yml` is branch-scoped, workflow_dispatch-capable and has an optional research-only push trigger for its own workflow file. **GitHub Actions scheduled cron only runs on a repository's default branch**, so no default-branch cron is installed. A branch-only push trigger must occur inside the user's Central execution window, and GitHub queue delays can cause the gate to close; in that case no provider calls or candidate evidence are claimed. No automation may spam repeated triggers, trigger after a completed capture for the session, or backfill a missed day using future snapshots. All actual captured artifacts must be inspected before being used for prospective evaluation. The test workflow runs both existing frozen journal and new capture unit tests offline.

The immediate research next steps are to collect genuinely prospective 2026+ sessions, measure provider missingness and independent issuer/session counts, independently verify corporate actions, market cap, security type and SMG borrow where possible, and compare **frozen** baseline/challenger against untouched outcomes with realistic slippage, exits, costs, squeezes and drawdowns. Do not optimize the -2% threshold using 2023–2025 or claim a tradable edge from price-only watches.

## Independent artifact integrity verification, 2026-10-26
