## P0-1 material finding and fix

The complete EOD source/conflict ledger (`backtest/obsidian_eod_conflict_inventory.py`) had a looser URL parser than the already hardened source preflight and exchange-calendar shadow. An arbitrary `https://other.example/calendar` assertion, or a URL with embedded userinfo, a nonstandard port, a trailing-dot hostname, a fragment, or control characters, could pass its **structural** calendar/source-host checks. That did not authenticate any actual official close, but could falsely suggest structurally adequate calendar/source provenance.

Implementation commit [d1c3520](https://github.com/Dirtyhandgernades/Dudebot/commit/d1c3520f13d277bab4316edcc96acc5e15d94eb3) now reuses the existing strict source URL guard and official NYSE/Nasdaq calendar-host allowlist. It keeps all supplied source rows, including a rejected third source whose parseable price disagrees across the 20% boundary; no rejected price is silently removed from the complete conflict inventory. Two regression methods cover unsafe calendar authorities and third-source URL claims with multiple synthetic subcases. This is only a syntax/host-claim check; a URL is not a retrieved or authenticated exchange receipt.

The initial hosted test run [41051138202](https://github.com/Dirtyhandgernades/Dudebot/actions/runs/41051138202) failed because the new synthetic control-character fixtures used a literal backslash-n instead of an actual newline. Test-only correction commit [48422f8](https://github.com/Dirtyhandgernades/Dudebot/commit/48422f8ce428fc2d9b27ed7da312463a7326525d) fixed the fixtures without relaxing the production-independent research guard. **Hosted [Actions run 41051222360](https://github.com/Dirtyhandgernades/Dudebot/actions/runs/41051222360) succeeded:** **515 prospective offline tests + 4 ABC-board tests = 519 total**, including both new regression methods.
